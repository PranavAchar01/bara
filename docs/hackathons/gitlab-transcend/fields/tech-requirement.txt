Tangible uses the GitLab Duo Agent Platform in three ways, all kept in .gitlab/duo/ in the repo. A custom flow, Tangible hardware gate triage, has two agent components. The first reads the failing hardware:gate job logs and the gate report. The second explains each KiCad error on the merge request and keeps one tracking issue per failing board. A custom agent, Tangible hardware reviewer, is there for questions about hardware merge requests in Duo Chat. An MCP server (.gitlab/duo/mcp.json) gives Duo the same checks as tools: list_boards, check_board, board_parts and export_fab. The flow and the agent are published in the GitLab AI Catalog and enabled on the project. The flow ran on merge request !1 (session 10098503, on a hosted runner). It read the failing pipeline, posted a triage note with each error and a suggested fix, and commented on the tracking issue for each failing board. Merge request pipelines feed it: they run KiCad 10 DRC and ERC, post the results on the merge request and label it.
